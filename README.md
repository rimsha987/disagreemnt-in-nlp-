# Filtering, Personas, and the Limits of Synthetic Annotator Diversity

Code, data records and results for a seminar study on annotator disagreement in DICES-350.

**Author:** Rimsha Abid (matriculation 7075879), Saarland University
**Seminar:** Disagreement in NLP
**Report:** [`tex/report_current.pdf`](tex/report_current.pdf)

The study asks whether two opposite-looking operations, removing "low-quality" raters and
simulating raters with demographic personas, both narrow the range of represented judgments.
Short answer: they fail differently, not alike. The published DICES filter is demographically
non-random but its pooled effect is indistinguishable from removing 19 raters at random at this
replication depth; the tested model produced no between-group variation distinguishable from its
own sampling noise.

Every number cited in the report is generated by the scripts here and listed with its source file
in [`results/SUMMARY_TABLE.md`](results/SUMMARY_TABLE.md). Nothing is transcribed by hand.

## What is and is not in this repository

Included: all analysis code, all computed results, all figures, and the complete raw model
responses (180 records, append-only).

**Not included:** the DICES dataset itself. It is released by Google LLC under CC BY 4.0 from its
own repository and is not redistributed here. The setup command below fetches it.

## Running Phase 2

**Free tier only. Nothing here is purchased.** Provider is `groq`, model `qwen/qwen3.8-27b`,
set in `src/phase2_config.py`; swapping is a one-line change and touches nothing else.

**The full run was never executed.** A 120-call diagnostic round showed that
`qwen/qwen3.8-27b` does not condition its ratings on demographic persona text: between-cell
differences (2/15 under v1, 3/15 under v2) sat inside the same-persona sampling noise floor
(mean 2.10/15, range 1-4), and the directional P(Yes) gap was +0.000 under v2 against a human
gap of +0.324. Per the decision rule fixed in advance, the LLM arm was stopped and Phase 3
proceeds with human conditions only. See FINDINGS.md 2.13. Total spend: 180 calls of a
budgeted 3,675.

The scaffolding is intact and reproducible should another model be tried: scope was
**175 items x 21 conditions = 3,675 calls, ~3.7 days** at Groq's 1,000 requests/day, with the
item sample frozen in `results/09_item_blocks.csv` (never redrawn) and the other 175 items held
as **block 2, a queued continuation** — `--blocks 1,2` extends the same item-keyed store and
re-runs nothing.

### Resumability

Every response is appended to a JSONL shard in `raw_responses/phase2/`, keyed by
`(item_id, condition)`, and flushed plus `fsync`ed **before the next call is made**. On restart
the runner reads every shard, skips completed keys, and retries anything whose `error` is
non-null. Worst-case loss on a crash, kill, quota wall, or power cut is **one call**.

Shards are append-only. Each session opens a new one; the runner refuses to overwrite. Re-run
the identical command to resume:

```bash
.venv/Scripts/python.exe src/07_run.py --mode full
```

`--status` shows progress and the wall-clock projection without calling anything. `--limit N`
caps a session. One Ctrl-C stops cleanly after the call in flight.

### Rate limits and quota

Groq publishes per-model free limits; they are transcribed in `src/phase2_config.py` with the
fetch date. Two facts worth knowing before a long run:

- Limits apply **per organisation**, not per key, so the pilot's 60 calls consume the same
  daily 1,000-request bucket as the run.
- Groq does **not** document when the daily bucket resets. The runner therefore captures the
  `x-ratelimit-*` headers on every call and prints them on the first call of each session;
  `x-ratelimit-reset-requests` is the only authority on reset timing.

Gemini config is retained but unused. Google no longer publishes free-tier figures, so those
values are an unverified placeholder and are marked as such in the config and in every
projection.

## Data notes

- Primary dataset is **DICES-350**: 350 conversations × 123 raters = 43,050 rows, fully crossed,
  zero missing values.
- **There is no quality-flag column.** The 19 removed raters are a hardcoded list in the
  dataset's own `350/README.md`; it is copied verbatim into `src/00_inspect_schema.py`.
- Primary label is `Q_overall` with three values: Yes / No / Unsure. "Unsure" is kept as a real
  category throughout, never collapsed or dropped. The one exception is the explicitly-labelled
  binary appendix in `src/03_filtering_labels.py`.
- No "Prefer not to answer" value exists in any demographic column; there are no nulls and no
  blanks. `rater_education` has a residual "Other" level (n=7).
- The `harm_type` grouping scheme was fixed before any RQ result was computed. It is defined in
  `src/harm_groups.py` and documented in `results/harm_type_grouping.md`. It is used in Phase 2
  only. Do not edit it now that Phase 1 results exist; add a second named scheme instead.

## Conventions that change the numbers

- **JSD** means the Jensen-Shannon **divergence** with base-2 logs, range [0, 1]. JS distance
  (its square root) is reported alongside where relevant.
- **Entropy** is Shannon, base 2, over 3 categories, so the maximum is log2(3) = 1.585.
- **Majority-label ties are counted explicitly**, never silently broken. The tie-aware flip
  count is the one quoted.
- Permutation tests use seed `20260826` and randomise **the rater set**, not items. Item-level
  tests over the 350 items are pseudo-replicated and are not used for inference — see
  FINDINGS.md §1.4.
- **TVD is the primary distributional metric**, JSD secondary, in every phase. Reason in
  FINDINGS.md §1.5.
- All file I/O is UTF-8. DICES conversations contain emoji, which crash the default Windows
  cp1252 console; set `PYTHONIOENCODING=utf-8` before running scripts that print conversations.
